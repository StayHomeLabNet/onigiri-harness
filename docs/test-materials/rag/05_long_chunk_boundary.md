# 長文運用ノート

## セクション1: 準備

運用担当者は開始前に対象機器、担当者、開始予定時刻を記録します。確認表にはネットワーク、保存容量、直近バックアップ、監視通知の状態を記載します。このセクションは長文資料が複数チャンクへ分割されることを確認するため、説明を詳しくしています。準備段階ではまだ復旧操作を始めません。

## セクション2: 通常確認

通常確認ではダッシュボードの状態、直近のイベント、処理待ち件数を順番に確認します。警告がある場合は、警告の発生時刻と対象を記録します。同じ警告が繰り返されていても、確認を省略してはいけません。担当交代時には、確認済みの範囲を次の担当者へ伝えます。

## セクション3: 連絡

連絡では状況を短くまとめ、観測した事実と推測を分けます。時刻は24時間表記を使い、対象の名前を省略しません。緊急度が不明な場合は中程度として扱い、責任者が再判定します。ここまでの手順には、テスト用の合言葉や復旧番号は含まれていません。

## セクション3.1: 状態の記録

状態の記録では、画面に表示された値を単位とともに転記します。推測した値や、前回の記録をそのまま使ってはいけません。複数の画面で値が異なる場合は、両方の値と確認時刻を残します。記録者は文章を短く保ちますが、対象を特定できる名前は省略しません。

## セクション3.2: 時刻の照合

時刻の照合では、端末の時刻、監視サービスの時刻、イベントに記録された時刻を比較します。時差が見つかった場合は修正せず、まず差分を記録します。夏時間や地域設定が影響する可能性も記載し、後から同じ順序で確認できるようにします。

## セクション3.3: 通知の整理

同じ原因から複数の通知が発生する場合があります。通知をまとめるときも、元の通知識別子は消しません。最初の通知、最後の通知、継続時間を記録し、途中で重要度が変化した場合は変化点を残します。通知を閉じる操作は責任者の確認後に行います。

## セクション3.4: 引き継ぎ

担当交代では、完了した確認、進行中の確認、まだ開始していない確認を分けます。次の担当者は引き継ぎ内容を復唱し、不明点をその場で確認します。口頭だけで完了させず、共通の記録欄へ同じ内容を残します。

## セクション3.5: 再確認

重大な判断の前には、対象名、環境、時刻、直近バックアップの4項目を再確認します。再確認で差異が見つかった場合は手順をいったん止め、差異の原因が分かるまで次へ進みません。再確認者は最初の確認者とは別の担当者にします。

## セクション3.6: 情報の分類

運用記録には公開可能、社内限定、制限付きの区分を付けます。区分が不明な情報は制限付きとして扱い、判断できる担当者へ確認します。このテスト資料に実在する秘密情報は含まれていませんが、分類手順の説明は通常資料と同じ形式にしています。

## セクション4: 境界に置く識別情報

災害復旧訓練で使う合言葉は「銀河スプーン」です。この合言葉は実在する認証情報ではなく、検索とチャンク境界確認専用の架空データです。合言葉を確認した担当者は、次のセクションに記載された復旧番号と組み合わせて訓練記録を検索します。

## セクション5: 復旧番号

「銀河スプーン」に対応する復旧番号はRK-2049です。別の訓練コードや受付番号と混同してはいけません。復旧番号を使った操作は架空であり、この資料はOnigiri Harnessのテストにだけ使用します。

## セクション6: 完了

訓練完了後は開始時刻、終了時刻、確認者、未解決事項を記録します。資料検索では合言葉と復旧番号の両方が回答に現れ、同じ資料の隣接チャンクが取得されることを確認します。
